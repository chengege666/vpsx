## sys_tools.sh：合并 IPv6 菜单（去掉原 18 项）

- 背景：系统工具菜单「4. 切换优先IPV4/IPV6」与「18. 开启系统 IPv6」功能重叠（4-4 与 18-1 完全等价的 `sysctl disable_ipv6=0`），且 4 混了"解析优先级"和"内核启停"两种语义。
- 改动（仅 modules/sys_tools.sh）：
  - 删除 `enable_ipv6_system` 函数（原 2010-2092 行），菜单项 18 移除。
  - 原 19-22 项重编号为 18-21：18 VPS安全入侵检测 / 19 SSH公钥登录配置 / 20 限制CPU使用率 / 21 Cloudflare Tunnel。
  - `switch_ip_priority` 重写为 8 个子项：设 IPv4 优先 / 恢复 IPv6 优先 / 开启 IPv6(临时) / 开启 IPv6(持久化) / 禁用 IPv6(临时) / 重启网络服务 / 取消持久化配置 / 测出口 IP。
  - 状态区新增第三行「重启后配置」，检测 `/etc/sysctl.d/99-ipv6-enable.conf` 是否存在。
  - 禁用 IPv6 时若存在持久化文件，提示重启后会被重新启用并引导先取消持久化（解决两处配置互相打脸的问题）。

  - `gai.conf` 回滚时若文件为空则删除（避免遗留用户当初并不存在的空文件）。

## 补充：禁用 IPv6 增加持久化（子项 6）

- 用户指出之前只有"禁用（临时）"，缺少持久化，与"开启"不对称。
- 新增子项 6「禁用系统 IPv6 (持久化)」：写 `/etc/sysctl.d/99-ipv6-disable.conf`（all/default/lo 全部 =1），并 `rm -f` 掉 `99-ipv6-enable.conf`；反向操作（子项 4）同样互删，保证两个文件不会同时存在。
- 状态区「重启后配置」改为三态：已持久禁用 / 已持久启用 / 未写入（按系统默认）。
- 子项 8「取消持久化」现在同时清理 enable 与 disable 两个文件。
- 子菜单最终为 9 项：1 IPv4优先 / 2 IPv6优先 / 3 开启临时 / 4 开启持久化 / 5 禁用临时 / 6 禁用持久化 / 7 重启网络服务 / 8 取消持久化 / 9 测出口 IP。
