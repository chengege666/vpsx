## 修复：禁用 IPv6 静默失败（用户反馈"禁用了但出口仍是 IPv6"）

- 现象：截图状态显示"内核 IPv6 状态: 启用"、出口 2401:b60:... 为 IPv6。根因是旧代码把所有 `sysctl -w` 的 stderr 丢进 `/dev/null`，写入失败仍打印"✅ 已禁用"。
- 新增 `apply_ipv6_profile <0|1>` 辅助函数：
  - 捕获 sysctl 的 stderr 并在失败时回显原始报错；
  - 写入后回读 `/proc/sys/net/ipv6/conf/all/disable_ipv6` 校验，不一致则报 ❌ 并提示 OpenVZ/LXC、/proc/sys 只读等原因；
  - 逐网卡兜底写 `/proc/sys/net/ipv6/conf/*/disable_ipv6`（部分内核 all 不回溯到已 up 网卡）；
  - 禁用后若仍有全局 IPv6 地址则告警。
- 子项 3/4/5/6 全部改为调用该函数，且只有校验通过才写持久化文件。
- 状态区新增「全局 IPv6 地址」行（`ip -6 addr show scope global`），可直接判断是否真断开。
- 子项 9 出口检测改为三行：默认出口 / 强制 IPv4(-4) / 强制 IPv6(-6)，便于判断哪套协议栈真的可用。
- 结论要点：gai.conf 只改解析排序，不等于禁用；IPv6 地址存在 + 目标有 AAAA 时仍可能走 IPv6。

## 确认环境限制：非特权容器，内核层禁用 IPv6 不可行

- 用户实测报错：`/proc/sys/net/ipv6/conf/all/disable_ipv6: Read-only file system`、`sysctl: permission denied on key "net.ipv6.conf.all.disable_ipv6"` → 判定为 LXC/OpenVZ 非特权容器，`/proc/sys` 只读，容器内无法修改 IPv6 内核开关。
- 修复上一版的两个问题：
  - 逐网卡兜底的重定向顺序写错（`> "$f" 2>/dev/null` 导致重定向失败信息仍外泄），改为 `2>/dev/null > "$f"`。
  - `apply_ipv6_profile` 增加预检：文件不存在 / 不可写时直接给一句话结论 + 替代方案，不再刷 8 行报错。
- 新增子项 10「阻断 IPv6 出站 (防火墙, 容器可用)」：
  - `ip6tables -I OUTPUT 1 ! -o lo -j DROP` 阻断（保留 lo），再执行则询问是否用 `-D` 解除，支持多条去重清理。
  - 失败时提示可能缺 NET_ADMIN，并给出删默认 IPv6 路由 / 服务商面板关闭两条退路。
  - 该规则重启失效，需重新执行（未做持久化，避免容器内 iptables-save 不可靠）。
- 待用户验证：第 9 项新增"强制 IPv4/强制 IPv6"两行，可判断是解析排序问题还是 IPv4 出站本身不通。
